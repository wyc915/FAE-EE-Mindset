# 18. 面試準備：流程、自介、行為題與情境題

> **一句話**：轉職面試的關鍵不是假裝懂內部流程，而是證明三件事：**基礎原理扎實、排查問題有方法、能把過去經驗轉換成新職位的價值**。本章整理通用的面試流程、自介範本、行為題與各職位的情境題。

## 學習目標

- 了解 FAE、設備、MFG、CIM、智慧製造、測試職位常見的面試流程與評分重點
- 寫出轉職者的履歷與 1 分鐘 / 3 分鐘自我介紹（中英文）
- 用 STAR 法回答行為面試題
- 用結構化框架回答各職位的技術情境題
- 準備反問問題與評估 Offer 的方法

## 1. 常見面試流程 🟢

```mermaid
flowchart LR
  A[投遞履歷<br/>104 / LinkedIn / 內推] --> B[HR 電話初篩]
  B --> C[筆試 / 線上測驗<br/>部分公司]
  C --> D[技術面試<br/>1～3 輪]
  D --> E[主管 / 跨部門面試]
  E --> F[HR 面談<br/>薪資與報到]
  F --> G[Offer]
```

| 公司類型 | 常見特色 |
|---|---|
| **晶圓廠 / 封測廠** | 可能有英文、邏輯或性格測驗；面試重視**基礎原理、抗壓、輪班意願、團隊合作** |
| **設備原廠（外商）** | 常有**英文面試**；重視問題排查思路、客戶溝通、出差與待命意願 |
| **IC 設計 / 外商半導體（FAE）** | 技術面試常考電路、量測、產品知識，並有**情境題**（客戶問題處理） |
| **代理商（FAE）** | 重視產品廣度、溝通與業務敏感度 |

**面試官在評估什麼**：

| 面向 | 他們想知道 |
|---|---|
| 技術基礎 | 原理懂不懂，還是只背名詞 |
| 問題排查 | 有沒有系統化的步驟，會不會先確認安全與收集資訊 |
| 學習能力 | 轉職者能多快上手 |
| 溝通 | 能不能把複雜問題講清楚 |
| 穩定性與動機 | 會不會很快離職；為什麼選這行 |
| 文化適應 | 輪班、出差、高壓環境的接受度 |

## 2. 履歷：把軟體經驗翻譯成新職位語言 🟢

| 軟體經驗 | 轉換成 |
|---|---|
| 線上事故排查 | **系統化故障排除**、根因分析、事後檢討（類似 8D） |
| 監控、告警、SLA | **可用率、MTTR、預警機制**（對應設備 Uptime、FDC） |
| 資料庫與報表 | **數據分析**、SPC、良率報表 |
| API 整合、訊息佇列 | **系統整合**、SECS/GEM、MES 介面 |
| 自動化腳本、CI/CD | **自動化**、減少人工作業、標準化流程 |
| 與 PM / 客戶溝通需求 | **客戶支援**、需求釐清、期望管理 |

**履歷原則**：
- 每段經歷用**動詞 + 做了什麼 + 量化成果**，例如「建立告警與自動復原機制，將平均修復時間從 2 小時降到 20 分鐘」
- 加一個「**轉職準備**」區塊：自學主題、實作作品（量測報告、SPC 分析、SECS 模擬器）、相關證照
- 依職缺關鍵字調整（FAE：電路、量測、客戶支援；設備：故障排除、數據分析、PM；CIM：C#、SECS/GEM、MES）

## 3. 自我介紹範本 🟢

### 1 分鐘（中文）

> 「您好，我是 ○○○，目前是軟體工程師，有 ○ 年經驗，主要使用 .NET 與資料庫開發系統，負責過 ○○ 系統的開發與維運。工作中我最有成就感的是處理跨系統的疑難問題，例如曾經 ○○（一句話成果）。
> 這半年我開始系統化學習 ○○（電子學與量測 / 半導體製程與設備），並完成 ○○ 作品（例如用 EVB 做電源量測報告 / 用 Python 做 SPC 分析）。
> 我希望把**問題排查、自動化與數據分析**的能力帶到 ○○ 職位，長期成為能同時處理軟硬體問題的工程師。」

### 1 分鐘（英文）

> "Hi, I'm ○○○, a software engineer with ○ years of experience building and maintaining systems with .NET and SQL databases. What I enjoy most is troubleshooting complex cross-system issues — for example, I ○○ (one-line result).
> Over the past six months, I've been studying ○○ (electronics and measurement / semiconductor processes and equipment) and built ○○ (a power-rail measurement report on an EVB / an SPC analysis in Python).
> I'd like to bring my troubleshooting, automation, and data analysis skills to this ○○ role, and grow into an engineer who can handle both hardware and software problems."

### 3 分鐘版本

在 1 分鐘版本的基礎上，加入：
1. **一個完整的 STAR 案例**（見第 4 節）
2. **作品細節**：做了什麼、遇到什麼問題、學到什麼
3. **為什麼是這家公司**：產品、技術、文化，要具體

## 4. 行為面試題（STAR 法）🟡

**STAR**：**S**ituation（情境）→ **T**ask（任務）→ **A**ction（你做了什麼）→ **R**esult（結果，盡量量化）

| 題目 | 回答重點 |
|---|---|
| 講一個你解決最困難問題的經驗 | 排查步驟要具體、展現假設與驗證，最後有量化結果與預防措施 |
| 你曾經犯過什麼錯？ | 誠實、說明如何補救與避免再發，不要選「致命」或「假裝的缺點」 |
| 與同事或客戶意見衝突時怎麼處理？ | 先理解對方立場、用數據討論、找共同目標、結果導向 |
| 同時有多件緊急事情怎麼排優先？ | 依**影響範圍、時效、安全**排序，並主動溝通取捨 |
| 在高壓下工作的經驗 | 說明你如何保持冷靜、拆解問題、維持溝通 |
| 如何快速學會新領域？ | 用本知識庫或作品集當例子 |
| 為什麼離開目前工作？ | 正面表述：追求的方向，不批評前公司 |
| 五年後的規劃？ | 與職位發展路徑一致（見[第 01 章](01-career-overview.md)） |

**範例（解決困難問題）**：
- **S**：系統每週會隨機當機一次，影響產線報表
- **T**：負責找出根因並避免再發
- **A**：先蒐集當機前後 Log 與資源使用率，發現記憶體逐漸上升；建立假設（連線未釋放），在測試環境重現，用 Profiler 確認是某段程式未關閉連線；修正後加上監控告警
- **R**：之後三個月零當機，並把排查流程寫成 SOP 分享給團隊
- **連結新職位**：「這個流程跟設備故障排除一樣：收集資料 → 建立假設 → 重現 → 驗證 → 預防再發」

## 5. 各職位情境題框架 🔴

> 通用框架：**安全 → 確認現象與範圍 → 收集資訊 → 隔離問題 → 驗證假設 → 解決與驗證 → 記錄與預防**

### 5.1 FAE

| 情境題 | 回答框架與參考章節 |
|---|---|
| 客戶產品隨機重開機 | Reset 原因 → 電源下陷 → 看門狗 → 干擾（[02](02-fae-technical-foundation.md)） |
| 客戶量產後不良率突然上升 | 圍堵 → 批次與變更 → ABA → FA → 8D（[03](03-fae-business-support.md)） |
| DC-DC 輸出振盪 | 負載暫態 / Bode → 輸出電容與補償 → Layout（[04](04-fae-power-ic.md)） |
| Wi-Fi 吞吐量低 | 隔離環境 → 無線指標 → 主機介面 → 設定（[05](05-fae-wireless.md)） |
| CAN Bus-off | 終端電阻 → 位元時序 → 波形 → 錯誤計數（[06](06-fae-automotive-mcu.md)） |
| 客戶堅持是晶片問題 | 數據、EVB 對照、ABA，提出合作方案（[03](03-fae-business-support.md)） |
| 兩個客戶同時要求你到現場 | 依營收影響、量產時程、嚴重度排序，與業務協調，提供遠端支援 |

### 5.2 設備工程師

| 情境題 | 回答框架與參考章節 |
|---|---|
| 半夜機台當機 | 安全 → 晶圓 → Log / FDC → 排除 → 升級 → 驗證 → 記錄（[08](08-equipment-engineering-practice.md)） |
| SPC 出現連續 8 點偏同一側 | 製程偏移 → 查變更、耗材、校正 → 與 PE 討論（[08](08-equipment-engineering-practice.md)） |
| 蝕刻速率逐漸下降 | 零件 RF 小時數、FDC、MFC、Seasoning（[09](09-etch-equipment.md)） |
| 薄膜微粒增加 | 清潔週期、Shield、排氣、微粒分布（[10](10-thin-film-equipment.md)） |
| CMP 刮傷增加 | 研磨液、過濾器、鑽石碟、研磨墊（[11](11-cmp-equipment.md)） |
| 鍵合機對位偏移 | 校正片、視覺、溫度、機構（[12](12-advanced-packaging-equipment.md)） |
| PM 後回機 Qualification 不過 | 檢查安裝、Pump Down / 漏率、Seasoning、子系統校正 |
| 如何提升機台 MTBF | 警報 Pareto → 前三大根因 → 對策 → 追蹤 |

### 5.3 CIM / EAP 工程師

| 情境題 | 回答重點 |
|---|---|
| 機台與 EAP 連線一直斷 | HSMS 連線狀態、T3 / T5 / T6 / T7 等計時器設定、網路、機台端 GEM 狀態 |
| 機台事件漏報 | 事件與報告是否正確定義與啟用、EAP 例外處理、訊息佇列 |
| 新機台導入要做哪些 | 確認 GEM 規格書、事件 / 變數 / 警報清單、配方管理、與 MES 流程對接、測試 |
| 如何設計高可用的 EAP | 重連機制、訊息持久化、監控告警、冪等處理（軟體背景強項） |
| 重複收到處理完成事件 | 冪等檢查、狀態機只接受合法轉移、持久化（[16](16-cim-engineering.md)） |
| 主機下遠端指令沒反應 | 查 GEM 控制狀態是否為 Online Remote（[16](16-cim-engineering.md)） |

### 5.4 MFG 製造工程師

| 情境題 | 回答框架與參考章節 |
|---|---|
| 產線 WIP 堆積、週期變長 | Little's Law → 找瓶頸 → 控制投片 → 降低變異（[15](15-mfg-manufacturing.md)） |
| 批次 Q-time 快超時但下游機台當機 | 停止上游投入、提高優先權、通知 EE、依規範 Hold（[15](15-mfg-manufacturing.md)） |
| SPC 超出管制 | OCAP：Hold 批次、Inhibit 機台、追溯範圍、判定（[15](15-mfg-manufacturing.md)） |
| 業務要求大量 Hot Lot | 說明對整體週期與產能的影響，提出分級與上限 |
| 技術員誤操作 | 先處置影響批次，再查 SOP、訓練與系統防呆 |

### 5.5 IMC 智慧製造

| 情境題 | 回答框架與參考章節 |
|---|---|
| 設計一個虛擬量測系統 | 資料來源與對齊 → 特徵 → 模型 → 部署 → 漂移監控 → 回饋 R2R（[17](17-imc-smart-manufacturing.md)） |
| 模型上線後準確度下降 | 檢查 PM / 耗材 / 配方變更、資料品質、特徵分布、再訓練（[17](17-imc-smart-manufacturing.md)） |
| 異常樣本極少 | 異常偵測、重新取樣、以成本選門檻、用 Recall 評估 |
| 工程師不信任 AI 結果 | 可解釋性、從輔助決策開始、用試行數據證明價值 |
| 設計即時機台資料管線 | 邊緣前處理 → Kafka → 時序庫 → 即時告警，考慮延遲與容錯 |

### 5.6 測試 / 產品工程師

| 情境題 | 回答框架與參考章節 |
|---|---|
| 良率突然下降 | Bin Pareto → Wafer Map → 排除測試端 → 製程端（[13](13-test-product-engineering.md)） |
| 某個 Site 不良率特別高 | 探針卡或 Socket 接觸、Site-to-Site 相關性 |
| 如何降低測試成本 | 多站並測、刪減項目、流程最佳化，以數據驗證品質 |

## 8. 反問問題與 Offer 評估 🟢

**可以反問的問題**：
- 這個職位新人前三個月的主要任務是什麼？
- 團隊如何培訓新人？有原廠訓練或導師制度嗎？
- 目前團隊最大的挑戰是什麼？
- 輪班 / 出差 / 待命的實際頻率？
- 這個職位成功的人通常具備什麼特質？

**Offer 評估面向**：

| 面向 | 要問清楚的事 |
|---|---|
| 薪資結構 | 本薪、固定獎金、績效獎金、分紅 / 員工酬勞、股票 |
| 工作型態 | 輪班制度、津貼、加班與待命、出差比例 |
| 成長 | 訓練資源、輪調機會、晉升路徑 |
| 地點 | 通勤、廠區位置、是否需要外派 |
| 技術方向 | 接觸的機台 / 產品是否為主流、可累積的技能 |

> 半導體與電子業的**獎金與分紅占總收入比例常很高**，比較 Offer 要看年度總薪酬，而不是只看月薪；同時考慮輪班與工時對生活的影響。

## 動手練習

1. **改寫履歷**：把你履歷中的 3 個經歷，依第 2 節的對照表改寫成目標職位的語言，並加上量化成果。
2. **錄自我介紹**：錄下中英文 1 分鐘自我介紹，回放檢查是否超時、是否有具體成果與作品。
3. **準備 5 個 STAR 故事**：困難問題、失敗、衝突、壓力、快速學習，每個寫成 4 句話。
4. **模擬情境題**：從第 5 節每個職位各挑 2 題，計時 3 分鐘口頭回答，再對照各章參考解答。

## 面試常問

> 先試著自己回答，再對照參考解答。

### Q1. 你沒有相關經驗，為什麼我們要錄取你？

回答結構：**可轉移能力 + 已做的準備 + 能帶來的額外價值**。

「雖然我沒有直接的 ○○ 經驗，但我在軟體工作中累積了系統化排查問題的能力，例如 ○○（STAR 簡述）。過去半年我自學了 ○○，並完成 ○○ 作品。此外，我能用程式與資料分析協助團隊自動化與改善，例如 ○○。我也了解新人需要從基礎做起，願意投入時間學習。」

### Q2. 你如何面對不懂的問題？

先坦白目前知道的範圍，再說明**解決路徑**：查閱手冊與規格書、比對歷史案例、請教資深同事或原廠（帶著自己的假設與已嘗試的步驟），解決後記錄下來成為知識。面試時遇到不會的題目，也可以用「我的推測是…，我會用…驗證」來展現思路。

### Q3. 你能接受輪班 / 出差 / 待命嗎？

誠實回答，並展現理解原因：「我了解機台停機或客戶量產問題需要即時處理，我可以接受。」如果有限制（家庭、健康），**在面試階段說清楚**，比錄取後才溝通更好。可以反問實際頻率與制度，表示你是認真評估。

### Q4. 你和主管意見不同時會怎麼做？

先理解主管的考量（可能有你不知道的資訊），用**數據與事實**提出自己的觀點與風險評估；若主管仍維持決定，會全力執行並追蹤結果，必要時再用結果回饋討論。重點是**對事不對人、結果導向**。

### Q5. 你最近學到的一個新技術是什麼？怎麼學的？

選一個與職位相關的主題（例如 SPC、Buck 設計、SECS/GEM），說明學習步驟：建立全貌 → 理解原理 → 動手實作 → 整理成筆記或作品。展現你有**自主學習的方法**，而不只是看過名詞。

## 常見誤解

- **「轉職者要把軟體經驗藏起來」**：相反，軟體與資料能力是差異化優勢，關鍵是**翻譯成對方需要的價值**。
- **「技術題答不出來就沒機會」**：面試官更看重思考過程，說出合理的假設與驗證方法通常比背答案更加分。
- **「月薪高的 Offer 就是最好的」**：要看總薪酬、工作型態、成長與技術方向。

## 本章回顧

- 流程：履歷 → HR → 筆試 → 技術面 → 主管 → HR；外商常有英文面試
- 履歷：把軟體經驗翻譯成排查、可用率、數據分析、系統整合
- 自介：背景 → 成果 → 轉職準備 → 想帶來的價值（中英文各備一份）
- 行為題用 STAR；情境題用「安全 → 範圍 → 資訊 → 隔離 → 驗證 → 解決 → 預防」
- 反問與 Offer 評估：看總薪酬、工作型態與成長
