# 05. FAE 產品線實務（二）：無線晶片（Wi-Fi / 藍牙）

> **一句話**：無線晶片的客訴大多不是「晶片壞了」，而是**天線、匹配、干擾、共存、省電設定與認證**。FAE 要同時懂 RF 量測與驅動 / 協定，是軟硬體能力都吃重的產品線。

## 學習目標

- 認識 Wi-Fi、藍牙與其他無線技術的世代與重點功能
- 掌握 RF 基本單位與指標：dBm、EVM、靈敏度、RSSI、VSWR
- 了解天線匹配、傳導 / 輻射量測與產線校正
- 熟悉各國認證（FCC、CE RED、NCC）與藍牙 SIG、Wi-Fi Alliance 認證
- 能排查吞吐量低、斷線、Wi-Fi / 藍牙共存、雜訊干擾（Desense）等問題

## 1. 無線技術地圖 🟢

| 技術 | 頻段 | 重點 | 典型應用 |
|---|---|---|---|
| **Wi-Fi 6 / 6E（802.11ax）** | 2.4 / 5 / 6GHz（6E） | OFDMA、1024-QAM、TWT 省電 | 手機、筆電、路由器 |
| **Wi-Fi 7（802.11be）** | 2.4 / 5 / 6GHz | **320MHz 頻寬、4096-QAM、MLO（多連結同時運作）** | 高階路由器、旗艦裝置 |
| **藍牙 Classic（BR/EDR）** | 2.4GHz | 連續串流 | 傳統耳機、車機 |
| **BLE（低功耗藍牙）** | 2.4GHz | 低功耗、廣播、LE Audio | 穿戴、感測器、Tag |
| **802.15.4（Thread / Zigbee）** | 2.4GHz | Mesh 網路，**Matter** 智慧家庭標準使用 Thread | 智慧家庭 |
| **UWB** | 6～9GHz | 精準測距與定位 | 數位車鑰匙、追蹤器 |
| **蜂巢式 IoT（LTE-M / NB-IoT）** | 授權頻段 | 長距離、低功耗 | 表計、資產追蹤 |

> 藍牙新版本持續加入功能，例如 **Channel Sounding**（藍牙 6.0）提供更精準的距離量測。台灣主要無線晶片公司有聯發科、瑞昱等，外商有 Qualcomm、Broadcom、Nordic、NXP、Infineon、Silicon Labs、Espressif 等。

### 系統架構

| 形式 | 說明 | 主機介面 |
|---|---|---|
| **Wi-Fi 網卡（NIC）** | 主處理器跑驅動，Wi-Fi 晶片跑韌體 | **PCIe、SDIO、USB** |
| **藍牙控制器** | 主機跑藍牙協定堆疊上層 | **HCI over UART / USB** |
| **無線 SoC** | 內含 MCU，應用程式直接跑在晶片上 | — |
| **Combo 晶片** | Wi-Fi + 藍牙同一顆，共用天線或 2.4GHz 射頻 | 分別或共用 |

## 2. RF 基本功 🟢

| 單位 / 指標 | 意義 | 記憶法 |
|---|---|---|
| **dBm** | 以 1mW 為基準的功率 | 0dBm = 1mW、20dBm = 100mW、−90dBm 極小 |
| **dB** | 兩者比值 | **+3dB ≈ 兩倍、+10dB = 十倍** |
| **TX Power** | 發射功率 | 受法規與 EVM 限制 |
| **EVM** | 調變品質（實際與理想星座點的誤差） | 高階調變（如 4096-QAM）要求極嚴 |
| **靈敏度（Sensitivity）** | 能正確接收的最小訊號 | 數值越負越好（如 −98dBm） |
| **RSSI / SNR** | 接收訊號強度 / 訊雜比 | 決定可用的調變速率 |
| **VSWR / Return Loss** | 天線與 50Ω 系統匹配程度 | 反射越少越好 |
| **路徑損耗** | 距離與障礙造成的衰減 | 距離加倍，自由空間損耗約 +6dB |

**連結預算（Link Budget）**：`接收功率 = TX 功率 + TX 天線增益 − 路徑損耗 + RX 天線增益`，接收功率高於靈敏度並保留餘裕（Fade Margin）才可靠。

## 3. 天線與匹配 🟡

- 天線要**匹配到 50Ω**，用 **π 型匹配網路**（兩個並聯、一個串聯元件）調整，在 **Smith Chart** 上觀察
- 用**網路分析儀**（VNA）量測 S11（回波損耗），在工作頻段一般希望 S11 低於約 −10dB
- **天線效率**比增益更重要，量測需在暗室進行
- **外殼、電池、金屬、人手**都會讓天線**頻率偏移（Detune）**，必須在**成品組裝狀態**下調匹配
- 常見天線：PCB 天線（便宜）、陶瓷晶片天線（小）、FPC 天線、外接天線

> 客戶最常見的錯誤：照參考設計畫了天線，但**淨空區（Keep-out）被地平面或元件占用**，或外殼是金屬。

## 4. 量測與產線校正 🟡

| 量測 | 方式 | 用途 |
|---|---|---|
| **傳導（Conducted）** | 從 RF 測試座接儀器 | 晶片與匹配電路本身的 TX / RX 指標 |
| **輻射（Radiated / OTA）** | 在暗室中量測 | **TRP**（總輻射功率）、**TIS**（總全向靈敏度），含天線影響 |
| **吞吐量** | iperf3、屏蔽箱 + 衰減器 | 速率與距離曲線（Rate vs Range） |
| **實際環境** | 多房間、多 AP、干擾環境 | 漫遊、穩定度 |

常見測試儀器：LitePoint、Rohde & Schwarz、Keysight、Anritsu 的無線綜合測試儀，以及頻譜分析儀、VNA。

**產線校正（Calibration）**：
- **頻率偏移校正**：校正晶振頻率誤差（ppm），寫入 eFuse / OTP / Flash
- **TX 功率校正**：各頻道、各速率功率對準目標，避免超過法規或功率不足
- **溫度補償**
- FAE 常協助客戶建立**量產測試程式與校正流程**，並解決校正良率問題

## 5. 認證 🟡

| 類別 | 認證 | 說明 |
|---|---|---|
| **美國** | **FCC Part 15** | 射頻發射限制 |
| **歐盟** | **CE RED** | 2.4GHz 參考 EN 300 328、5GHz 參考 EN 301 893；**RED 網路安全要求（EN 18031 系列）自 2025 年 8 月起適用**於聯網無線產品 |
| **台灣** | **NCC** | 低功率射頻器材審驗 |
| **其他** | 日本 MIC / TELEC、中國 SRRC、韓國 KC 等 | 各國不同 |
| **協會** | **Bluetooth SIG Qualification**、**Wi-Fi Alliance Certification** | 使用商標必須通過 |

- **模組化認證（Modular Approval）**：用已認證的模組可大幅簡化終端產品認證，是小量客戶選模組而非晶片的主因
- **5GHz DFS**：部分頻道須偵測雷達並避讓，認證必測
- FAE 常提供**認證用測試模式工具**（固定頻道、連續發射）與參數表（功率表、Regulatory Domain 設定）

## 6. 常見客訴與排查 🔴

| 現象 | 可能原因 | 排查 |
|---|---|---|
| **吞吐量低** | 干擾、頻寬設定、天線、省電、主機介面瓶頸（SDIO 時脈、PCIe 鏈路速度）、CPU 負載 | 屏蔽箱傳導測試排除環境；看 RSSI、MCS、重傳率；檢查主機匯流排 |
| **斷線 / 掉線** | 省電模式（Beacon 遺失、DTIM）、漫遊設定、AP 相容性、韌體 | 抓空中封包（Sniffer）、驅動 Log、關閉省電比較 |
| **Wi-Fi / 藍牙同時用時變差** | **2.4GHz 共存**：共用天線切換、PTA 仲裁設定 | 調整共存參數、天線隔離度、Wi-Fi 改用 5GHz |
| **特定情況靈敏度下降（Desense）** | 板上雜訊：**USB 3.x 雜訊落在 2.4GHz**、DDR、DC-DC、LCD / 相機介面 | 開關各干擾源比較靈敏度、頻譜儀找雜訊、加屏蔽、改 Layout |
| **BLE 連線不穩或耗電高** | 連線參數（Connection Interval、Latency、Supervision Timeout）、廣播間隔 | 用 BLE Sniffer 看參數協商，依應用調整 |
| **產線良率低** | 校正流程、測試治具接觸、屏蔽箱干擾 | 量測重複性、治具校驗 |
| **認證失敗** | 功率表設定、諧波、雜散發射 | 調功率表、加濾波、檢查 DC-DC 雜訊 |

**除錯工具**：
- **Wi-Fi**：Wireshark + 監聽模式網卡、`iw`、`wpa_supplicant` Log、驅動 Debug Log
- **藍牙**：`btmon` / HCI Log、Android 的 **btsnoop** Log、專業空中分析儀（如 Ellisys）、Nordic nRF Sniffer（BLE）

> 這些除錯方式跟軟體網路除錯（抓封包、看 Log）非常相似，是軟體背景的強項。

## 動手練習

1. **dB 心算**：TX 20dBm、天線增益 2dBi、路徑損耗 80dB、RX 天線 0dBi，接收功率多少？若靈敏度 −90dBm，餘裕多少？
2. **抓封包**：用 Linux 筆電或 USB 網卡設定監聽模式，用 Wireshark 抓 Beacon，找出 DTIM、支援速率、頻道寬度。
3. **BLE 實驗**：用 ESP32 或 nRF52 開發板做一個 BLE 周邊，用手機 App（如 nRF Connect）連線，改變 Connection Interval 並量測耗電差異。
4. **iperf3 測試**：在不同距離與頻段（2.4 / 5GHz）測量吞吐量，畫出 Rate vs Range 曲線。

## 面試常問

> 先試著自己回答，再對照參考解答。

### Q1. dBm 和 dB 的差別？

- **dBm** 是**絕對功率**，以 1mW 為基準：`dBm = 10 × log10(P / 1mW)`
- **dB** 是**相對比值**，用於增益、損耗
- 運算規則：dBm ± dB = dBm，例如 10dBm 經過 3dB 損耗剩 7dBm

### Q2. 客戶反映 Wi-Fi 吞吐量很低，怎麼排查？

1. **隔離環境**：在屏蔽箱或傳導環境下測試，若正常 → 問題在天線或環境干擾
2. **看無線指標**：RSSI、實際 MCS、頻寬、重傳率、頻道擁擠度
3. **主機端**：SDIO 時脈、PCIe 鏈路速度、USB 模式、CPU 使用率、驅動版本
4. **設定**：省電模式、頻寬（20 / 40 / 80MHz）、Regulatory 設定、天線數（MIMO）
5. **對照組**：同一環境用參考板比較

### Q3. 什麼是 Desense？如何排查？

**Desense**（減敏）是板上其他電路產生的雜訊落在接收頻段，墊高雜訊底層，使接收靈敏度變差。排查方法：在傳導或 OTA 環境下量靈敏度，**逐一關閉可能的干擾源**（USB 3.x、DDR、DC-DC、顯示器、相機）比較差異；用頻譜分析儀與近場探棒找出雜訊源。對策包含屏蔽罩、濾波、Layout 調整、改變切換頻率或時脈展頻。

### Q4. Wi-Fi 和藍牙如何共存？

兩者都使用 2.4GHz，常見方法：
- **PTA（Packet Traffic Arbitration）**：晶片間或晶片內部依優先權分配時間（TDM）
- **天線隔離**：獨立天線並保持足夠隔離度
- **頻率避讓**：藍牙**適應性跳頻**（AFH）避開 Wi-Fi 使用的頻道
- 讓 Wi-Fi 優先使用 5 / 6GHz，減少 2.4GHz 衝突

### Q5. 為什麼成品的天線要重新調匹配？

天線的阻抗與共振頻率會受周圍環境影響：外殼材質、電池、金屬件、螢幕、人手都會造成**頻率偏移**與效率下降。參考設計的匹配值只適用於參考板，必須在**最終組裝狀態**下用 VNA 量測並重新調整匹配元件。

### Q6. BLE 的連線參數如何影響功耗與延遲？

- **Connection Interval**：兩次連線事件的間隔，越長越省電但延遲越高
- **Peripheral Latency**：周邊可跳過的連線事件數，提高省電
- **Supervision Timeout**：多久收不到封包就判定斷線，必須大於 `(1 + Latency) × Interval × 2`

應用要在**省電、反應速度、連線穩定度**之間取捨，例如感測器用長間隔，遊戲手把用短間隔。

## 常見誤解

- **「TX 功率越大越好」**：受法規限制，且功率過高會讓 EVM 變差，高階調變反而降速。
- **「訊號格數滿就代表速度快」**：干擾、頻道擁擠、主機介面瓶頸都會限制速度。
- **「認證是最後才要煩惱的事」**：天線、濾波、功率表設計在前期就要考慮認證，否則後期改板代價很大。

## 本章回顧

- 技術地圖：Wi-Fi 6 / 6E / 7（MLO、320MHz）、BLE、Thread / Matter、UWB
- RF 基本功：dBm、+3dB 兩倍、EVM、靈敏度、Link Budget
- 天線必須在成品狀態調匹配；量測分傳導與 OTA（TRP / TIS）
- 認證：FCC、CE RED（含網路安全）、NCC、藍牙 SIG、Wi-Fi Alliance
- 客訴前三名：吞吐量低、斷線、共存與 Desense；抓封包與看 Log 是軟體背景的強項
